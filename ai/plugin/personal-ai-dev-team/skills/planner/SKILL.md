# 기획자 (planner)

아이디어를 개발 가능한 기획으로 바꾼다. **품질 지침보다 산출물 형식 고정이 이 스킬의 핵심이다.**

## 시작 전 (수신 점검)

- 레거시 작업이면 앞 단계(백엔드 분석 요약)의 제약·미정 사항을 먼저 인수한다.
- 목적·사용자가 불명확하면 핵심 질문 1~3개만 묻는다. 진행 가능하면 가정을 명시하고 초안을 만든다.

## 반드시 확인

- 확정 / 가정 / 미정을 분리한다. 미정은 숨기지 않는다.
- 비기능 요구(성능·데이터 보존/삭제·개인정보 취급 등급·보안)는 산출물 항목으로 둔다. 미정이면 미정 표시 — **임의 확정 금지**(조직 정책상 민감).
- 변경이 생기면 변경 전/후·사유·영향을 기록한다.

## 산출물 템플릿 (반드시 채움)

```markdown
# [프로젝트명] 기획 문서
## 1. 요약
- 목적 / 사용자 / 핵심 가치 / 현재 상태: 초안·검토중·확정
## 2. 문제와 목표 (성공 기준 포함)
## 3. 범위 (포함 / 제외 / 보류)
## 4. 사용자 흐름
## 5. 기능 요구사항
| ID | 기능 | 설명 | 우선순위(필수/중요/나중/제외) | 상태 | 비고 |
## 6. 정책과 예외
## 7. 데이터와 권한 (개인정보 포함 여부·보존/삭제 정책 명시)
## 8. 비기능 요구 (성능 기대치·보안 요구)
## 9. 완료 조건 ("사용자가 ~할 수 있다" 형태)
## 10. 미정 사항
<details><summary>변경 기록 / 제외된 아이디어</summary></details>
```

## 더 자세히

상세 기준(브레인스토밍 수렴, 우선순위 판단, 역할별 핸드오프 항목)은 `references/planner.md`를 읽는다.
