본인의 관련 커밋을 합친다(스쿼시). 안전장치를 **모두** 지킨다.

## 진행 전 게이트 (하나라도 어기면 중단)

1. **시작 지점 명시 필수** — 사용자가 시작 커밋을 지시하지 않았으면(`$ARGUMENTS`가 비었으면) **진행하지 않고** 어느 커밋부터 합칠지 묻는다. 범위를 추측하지 않는다.
2. **본인 작업만** — `git config user.email`로 현재 작성자를 읽고, 합칠 범위(`$ARGUMENTS..HEAD`)의 **모든 커밋 작성자가 현재 사용자와 일치**하는지 확인한다. 다른 작성자 커밋이 섞이면 중단하고 알린다.
3. **이미 공유된 커밋 제외** — 합칠 범위가 `origin/<base>`보다 앞선(아직 push 안 된) 커밋인지 확인한다. base에 이미 올라간 커밋이 포함되면 중단한다.
4. **브랜치 확인** — 현재 브랜치가 main/master면 **중단**(조직 정책: main 직접 변경 금지). feature 브랜치에서만.

## 미리보기 → 승인 → 실행

5. **미리보기** — 합쳐질 커밋 목록(`git log --oneline $ARGUMENTS..HEAD`)과 합쳐진 뒤의 커밋 메시지(안)를 보여준다. 실제 변경 없이 보여주기만 한다.
6. **승인 후 실행** — 사용자가 승인하면 비대화식으로 합친다(이 환경은 `git rebase -i` 미지원):
   `git reset --soft <시작 커밋>~1 && git commit -m "<합친 메시지>"`
7. **푸시는 별도 확인** — 히스토리 재작성은 비가역이다. 푸시 전 원격에 새 커밋이 있는지 확인하고, force-push는 본인 feature 브랜치에서 **명시 승인 시에만** 한다.

> 합치기 전 작업 트리가 깨끗한지(uncommitted 변경 없는지) 확인한다. 불확실하면 백업 브랜치를 먼저 만들 것을 제안한다.
