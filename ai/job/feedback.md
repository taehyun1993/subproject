# AI 작업 피드백 운영 가이드

이 문서는 사용자와 AI가 함께 작업하면서 발생한 오류, 누락, 비효율을 기록하고 개선 규칙으로 바꾸는 기준을 정의한다. 목적은 매번 사용자가 따로 지시하지 않아도 작업 흐름 안에서 피드백이 자동으로 감지되고 누적되게 하는 것이다.

## 1. 한 문장 정의

피드백은 비난이 아니라 다음 작업의 품질을 높이기 위해 문제, 원인, 개선 규칙을 남기는 작업이다.

## 2. 기본 원칙

- 피드백은 항상 감지하되, 항상 길게 보고하지 않는다.
- 위험한 문제는 즉시 공유하고 수정한다.
- 일반 개선점은 작업 종료 시 짧게 정리한다.
- 사소한 개선점은 누적해두고 주기적으로 정리한다.
- 사용자 지시 문제와 AI 실행 문제를 구분한다.
- 같은 문제가 반복되면 역할 문서나 workflow.md에 반영한다.
- 피드백은 사람 탓이 아니라 시스템 개선 기준으로 기록한다.

## 3. 피드백 대상

| 대상 | 의미 | 예시 |
| --- | --- | --- |
| 사용자 지시 | 요청 방식, 완료 기준, 우선순위가 불명확했던 경우 | 범위가 모호함, 검증 기준 없음 |
| AI 실행 | AI가 요구사항을 오해하거나 잘못 수행한 경우 | 엉뚱한 파일 수정, 검증 누락 |
| 역할 판단 | 필요한 역할을 잘못 선택하거나 생략한 경우 | 디자이너 검토가 필요한데 생략 |
| 워크플로 | 작업 순서, 핸드오프, 완료 기준이 부족했던 경우 | API 영향 확인이 늦음 |
| 문서/스킬 | 역할 문서나 스킬 지침이 부족했던 경우 | 기존 화면 단순 추가 기준 누락 |

## 4. 심각도와 처리 방식

| 심각도 | 기준 | 처리 방식 |
| --- | --- | --- |
| 높음 | 데이터 손실, 보안, 권한, 결제, 배포, 잘못된 파일 수정, 핵심 요구사항 누락 | 즉시 보고하고 수정한다 |
| 중간 | 작업 방향 오류, 검증 누락, 역할 판단 오류, 일정/영향 범위 누락 | 현재 작업 완료 보고에 포함한다 |
| 낮음 | 표현, 질문 방식, 문서 구조, 효율 문제 | 누적 기록 후 주기적으로 정리한다 |

## 5. 즉시 피드백 조건

다음 상황은 작업 중이라도 즉시 피드백한다.

- 사용자의 핵심 요청을 잘못 이해했다.
- 요청하지 않은 파일이나 범위를 수정했다.
- 기존 사용자 변경을 되돌릴 위험이 있다.
- 검증하지 않았는데 완료처럼 말할 위험이 있다.
- 데이터 손실, 보안, 권한, 결제, 정산, 배포에 영향을 줄 수 있다.
- 같은 실수를 반복하고 있다.
- 더 진행하면 비용이 커지는 방향 오류를 발견했다.

즉시 피드백 형식은 짧게 유지한다.

```markdown
## 즉시 피드백
- 문제:
- 영향:
- 바로잡을 행동:
```

## 6. 작업 종료 시 피드백 점검

모든 작업 종료 시 다음 질문을 짧게 확인한다.

- 사용자의 요청을 정확히 이해했는가?
- 처음 정한 범위를 벗어나지 않았는가?
- 필요한 역할을 생략하지 않았는가?
- 검증하지 못한 것을 완료처럼 말하지 않았는가?
- 미정 사항이나 남은 리스크를 숨기지 않았는가?
- 다음 작업부터 바꿔야 할 규칙이 있는가?

문제가 없으면 길게 쓰지 않고 `특이 피드백 없음`으로 처리할 수 있다.

## 7. 피드백 기록 형식

감지된 피드백은 누적 로그 파일 `feedback/feedback-log.md`에 다음 형식으로 한 줄씩 쌓는다. 위험한 문제는 즉시 기록하고, 일반 개선점은 작업 종료 시 기록한다.

| 날짜 | 대상 | 심각도 | 문제 | 원인 | 개선 규칙(후보) | 반영 위치(후보) | 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| YYYY-MM-DD | 사용자 지시 / AI 실행 / 역할 판단 / 워크플로 / 문서·스킬 | 높음 / 중간 / 낮음 |  |  |  | workflow.md / 역할 문서 / 보류 | 미반영 / 반영 |

개선 규칙과 반영 위치는 기록 시점에는 "후보"로 두고, 주기적 롤업(§8, §11)에서 확정한다. 누적·롤업·반영의 전체 흐름은 §11 피드백 파이프라인을 따른다.

## 8. 누적 피드백 정리 방식

피드백이 쌓이면 일정 주기로 정리(롤업)한다. 기준은 시간보다 양과 반복성이다. 정리는 `/feedback-review` 명령으로 수행한다.

정리 시점은 다음 중 하나로 한다.

- 피드백이 5개 이상 쌓였을 때
- 같은 문제가 2번 이상 반복됐을 때
- 큰 작업이 끝났을 때
- 사용자가 "피드백 정리"를 요청했을 때
- 역할 문서나 workflow.md 수정이 필요해졌을 때

`/feedback-review`는 `feedback-log.md`를 읽어 반복 패턴을 추출하고 두 가지를 만든다.

- 사람용 요약: `feedback/feedback-report.md` (무엇이 반복되는지, 권장 개선)
- AI용 수정안: workflow.md / 역할 문서 / SKILL.md / references 에 대한 diff 제안

수정안은 **사용자가 승인한 것만** 실제 문서에 반영한다(기준 문서가 말없이 바뀌는 것 방지). 반영된 로그 항목은 상태를 `반영`으로 갱신한다. 일회성 이슈는 보류로 두고, 문서 반영이 부적절하면 사용자 작업 방식 개선 제안으로 남긴다. 어느 반복 문제를 어느 문서에 반영할지는 §10 표를 근거로 한다.

## 9. 피드백 요약 형식

작업 완료 보고에 피드백을 포함할 때는 짧게 쓴다.

```markdown
## 피드백
- 즉시 반영할 문제:
- 누적 기록할 문제:
- 문서에 반영할 후보:
```

문제가 없으면 다음처럼 쓴다.

```markdown
## 피드백
- 특이 피드백 없음
```

## 10. 역할 문서 반영 기준

피드백이 반복되면 반드시 문서에 반영한다.

| 반복 문제 | 반영 위치 |
| --- | --- |
| 요구사항 범위가 자주 흔들림 | workflow.md, planner.md |
| 기존 디자인 추가 작업에서 과설계 | ui_ux_designer.md, frontend_developer.md |
| API/DB 영향 누락 | backend_developer.md, workflow.md |
| 화면 상태 처리 누락 | ui_ux_designer.md, frontend_developer.md |
| 검증 누락 | workflow.md, backend_developer.md, frontend_developer.md |
| 완료 보고가 부정확함 | workflow.md, feedback.md |

## 11. 피드백 파이프라인

이 문서의 기준이 실제로 누적·반영되도록, 피드백은 다음 4계층 파이프라인으로 운영한다. 대상 오류는 두 출처를 모두 포함한다.

- ① 사용자가 잘못 전달해 AI가 오류로 처리한 경우 (대상: 사용자 지시)
- ② AI가 잘못 처리해 오류가 난 경우 (대상: AI 실행)

```text
(A) 감지        (B) 누적            (C) 주기적 롤업          (D) 반영
AI 자동 감지  →  feedback-log.md  →  /feedback-review     →  승인 후
+ hook 알림      (raw 원장)           ├ feedback-report.md     역할·워크플로 md 수정
                                     └ md 수정안(diff)         (사용자 승인분만)
```

### (A) 감지

- AI가 교정·오류 순간을 스스로 인식해 §7 형식으로 로그에 기록한다(의미 판단은 AI 담당).
- hook(Stop / UserPromptSubmit)이 교정 신호("아니", "그게 아니라", "잘못", "다시", 되돌림·재작업 등)를 포착하면 "이 건을 로그에 기록했는가"를 리마인드해 누락을 막는다.

### (B) 누적

- 모든 오류·교정을 `feedback/feedback-log.md`(§7 형식)에 그대로 쌓는다. 이 단계에서는 판단하지 않고 사실만 남긴다.

### (C) 주기적 롤업

- §8 시점에 `/feedback-review`로 로그를 정리해 사람용 요약(`feedback-report.md`)과 AI용 수정안(diff)을 만든다.

### (D) 반영

- 수정안은 사용자가 승인한 것만 AI가 보는 문서(workflow.md, 역할 문서, SKILL.md, references)에 반영한다.
- 어떤 반복 문제를 어느 문서에 반영할지는 §10 "역할 문서 반영 기준" 표를 근거로 한다.
- 반영된 로그 항목은 상태를 `반영`으로 갱신한다.

### 파일 구조

| 파일 | 역할 | 누가 보나 |
| --- | --- | --- |
| `feedback/feedback-log.md` | 오류·교정 누적 원장 (raw) | AI(기록), 필요 시 사람 |
| `feedback/feedback-report.md` | 주기적 롤업 요약 | 사람 |
| `workflow.md` / 역할 문서 / SKILL.md / references | 승인된 개선 규칙이 반영되는 곳 | AI |
